# ADR-0120: Grammalecte-Derived Participle-Family Bridge for Grid Dedup

## Status
Accepted

## Context
ADR-0119 adopted Démonette-2 as the canonical derivational-morphology
resource and deferred the family-aware `WordAcceptor` dedup fix (its
roadmap item 1) to its own ADR, on the assumption that fix would be built
on Démonette-2.

A narrower, live defect surfaced first and does not need Démonette-2's
general derivation graph: a French **participle** has a dual identity in
grammalecte's tagging — it is analysed BOTH as a verb form (`ppas`/`ppre`,
lemma = the verb infinitive) and as an adjective with its own lemma. Our
corpus keeps one lemma per surface, so an inflected participle-adjective
(`émanée`, lemma `émané`) is severed from its verb (`émaner`) for grid
dedup purposes. The existing same-lemma dedup already bridges surfaces
that carry more than one corpus lemma (`abaissée` → `{abaissée, abaisser}`),
but épicène-invariable participles attach the verb reading only to the
invariable base form, so gendered adjective forms slip through —
**605 corpus surfaces across ~500 families** (measured against the real
corpus, `ParticipleFamilyDedupGateTest`'s deterministic key gate).

This is inflectional/tagging noise, not a derivational relation — grammalecte
already asserts both lemmas for the same surface; nothing needs to be
*derived*. Waiting for the Démonette-2-based general fix would leave this
specific, already-measured, already-diagnosed defect (`ÉMANÉE` + `ÉMANER`
on one grid) live in production with no timeline.

## Decision
Ship a narrow, interim bridge scoped to grammalecte's participle
double-tagging, ahead of and independent from the general Démonette-2-based
`WordAcceptor` fix that ADR-0119 roadmap item 1 still owns:

- `scripts/grid_family/build_participle_family_edges.py` reads the
  grammalecte lexique and emits `adj-lemma -> verb-lemma` edges for every
  surface grammalecte tags as both an adjective and a verb participle,
  folded to grid-cell A-Z uppercase (`Word.lemma` form).
- `grid/infrastructure/src/main/resources/morphology/participle_family_edges.csv`
  is the generated artifact — a **main resource**, so the deployed worker
  loads it (unlike the Démonette-2 derivation graph, which ADR-0119 keeps
  internal/uncommitted under the ShareAlike posture; grammalecte's lexicon
  is not licence-restricted the same way and this artifact carries no
  Démonette-2 data).
- `CsvWordRepository` loads the edges and completes the per-surface lemma
  key so `WordAcceptor` blocks the family on every generation path (dense
  and distilled).
- `ParticipleFamilyDedupGateTest` (opt-in, `@Tag("bench")`) is the
  independent gate: a deterministic key-bridging check (the real guard,
  since the generation-level manifestation is rare per grid) plus a fleet
  generation check against an independent grammalecte oracle.

**Relationship to ADR-0119.** This does not replace or pre-empt the
Démonette-2-based fix — that fix generalises to *derivational* relatives
(`tir`/`tirer`, `laver`/`lavage`), a strictly larger problem this bridge
does not touch. When the general fix lands, `WordAcceptor` will consume
both edge sets (this one for the participle double-tagging case,
Démonette-2's for genuine derivation); this ADR's edges are not
superseded by that work and can stay.

## Consequences
**Easier:**
- The measured, diagnosed `ÉMANÉE`/`ÉMANER`-class defect is fixed now,
  without waiting on the Démonette-2 ingest or its own ADR/PR.
- The fix is small, deterministic, and independently gated — no LLM
  judgment, no licence posture to reconcile (grammalecte's lexicon is
  already a build-time dependency elsewhere in the pipeline).

**Harder / new:**
- A second, narrower edge resource alongside the eventual Démonette-2
  derivation graph — two sources for `WordAcceptor` to consult once ADR-0119
  roadmap item 1 lands, not one. Kept deliberately separate: this bridge is
  inflectional-tagging noise, Démonette-2 is derivational relation.
  `docs/adr/INDEX.md` carries entries for both paths so this is visible to
  future agents.
- `participle_family_edges.csv` must be regenerated by
  `build_participle_family_edges.py` on a grammalecte lexique bump; it is
  not kept in sync automatically.

**Different:**
- Unlike the Démonette-2 graph, this artifact ships in the repo and image
  (it is derived from grammalecte's open lexicon, not a licensed corpus),
  so it needs no ADR-0058 licence-matrix entry.
