# ADR-0095: Low-Density Daily Grid Generation (Anchored Runs + Per-Axis Caps + Best-of-N)

## Status
Accepted

## Context
Daily grids generated by the ADR-0039 bitmask-CSP generator settle at ~26–28%
black-cell density. Published French *mots fléchés* run sparser (~18–22%), and
the maintainer flagged the daily grids as visibly too dense.

The density is not a bug in a single knob: it is an emergent property of the
seed→fill→perturb loop. `BlackCellLayout.seed` targets ~14% black, but when a
sparse layout fails to fill within the CSP backtrack budget, `GridGenerator`
perturbs (adds blacks) until it fills — converging on ~26%. Measured facts
(bench, 28×20, clued corpus):

- Simply raising the backtrack budget does **not** help: even 2M backtracks
  fail to fill a sparse seed on attempt 1, and bigger budgets mean fewer
  perturbation cycles, so success *drops*.
- The corpus is long-word-rich (86% ≥8 letters) but short-word-poor; short
  fillers are the scarce resource that lets sparse layouts complete (see the
  sigle-corpus additions shipped alongside).

## Decision
Add three composable, opt-in generation levers and a daily config that uses
them. All are gated (default off), so non-daily generation is unchanged.

1. **Per-axis run caps** — `GridConstraints.lTargetHorizontal` /
   `lTargetVertical` (default `null` → the existing single `lTarget`). Lets the
   seed target different maximum run lengths per axis; `BlackCellLayout` caps
   long horizontal/vertical runs independently.
2. **Anchored long runs** — `LayoutAnchorer.carve` extends the longest run in
   `anchorCount` evenly-spaced rows up to `anchorLength`, each step validated.
   Unlike a global cap raise, only K slots get long, so the CSP keeps a
   comfortable board everywhere else and **perturbation stays on** — the board
   remains fillable.
3. **Best-of-N selection** (daily pre-gen path) — generate N candidates and
   keep the one with the fewest black cells.

**Daily config:** `anchorCount = 3`, `lTargetHorizontal = 11`,
`lTargetVertical = 8`, best-of-8. A config sweep confirmed this is the sweet
spot; pushing anchors/caps harder allows runs the CSP cannot fill → more
perturbation → *denser* boards.

## Rejected
`LayoutDistiller` (a greedy black-cell minimizer) was prototyped and **not
shipped**. To preserve the structure it thins, it disables perturbation; a
distilled sparse seed that fails to fill then has no fallback, so generation
gives up. It produced zero valid boards at every budget, with or without the
enriched corpus.

## Consequences
- Black density on the clued corpus drops from ~28% (live) to **~23% average /
  21% best**, with two-letter-word share falling ~33% → ~22% (better quality).
- Best-of-N costs N× generation per grid. Negligible for the daily pre-gen
  CronJob (a handful of puzzles/day); the interactive on-demand path keeps N=1.
- The density win depends on the enriched short-word corpus (the sigle
  overlay); without it, aggressive anchors densify rather than thin.
- **Daily grids are 22×15, decoupled from the 28×20 API default.** The daily
  path builds `dailyPuzzleConstraints()` (its own size + knobs), while the
  on-demand API generator keeps `defaultPuzzleConstraints()` at 28×20. The
  low-density knobs are re-scaled to the smaller board — `anchorCount = 3`,
  `anchorLength = 10`, `lTargetHorizontal = 9`, `lTargetVertical = 6` (per-axis
  caps kept near the same fraction of each dimension as the 28×20 config).
  Feasibility gate on the clued corpus: 12/12 fill, ~24.7% avg / 23.0% best
  definition-cell density, <70 ms/gen — comparable to the 28×20 result.
  Regenerating already-persisted dailies at the new size is an operator step
  (`grid-worker --regenerate-dailies`), not part of the config change.
